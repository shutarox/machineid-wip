# CLAUDE.md の再構成と定型手順のスキル化(4-2)

作成: 2026-08-04

## 目的

CLAUDE.md を **「全体地図 + 判断基準」だけ**に絞り、**手順書は `.claude/skills/` のプロジェクトスキルへ移す**。

現状の CLAUDE.md は 238 行で、次の 3 つが混在している。

| 種類 | 例 | あるべき場所 |
|---|---|---|
| **判断基準**(なぜそうするか) | 層構造は 3 層 / RHF は購読 API 縛り / 日時は JST 正準形 | **CLAUDE.md** |
| **地図**(どこに何があるか) | 主要ファイルの場所 / ドメイン概念 | **CLAUDE.md** |
| **手順**(何をどの順で叩くか) | スキーマ変更 → migrate:create → migrate:deploy → db:generate | **`.claude/skills/`** |

手順が本文に混ざっていると、**毎セッション全文がコンテキストに載る**一方で、実際に手順が必要なのは「スキーマを変えるとき」だけ。判断基準は常時必要、手順は随時必要、という頻度の差が構造に反映されていない。

## 根拠: 受け入れテストで実際に詰まった場所

2026-08-04 の受け入れテスト(新規セッションのエージェントに CRUD 追加を丸投げ)で、**エージェントは層構造・スキーマ変更手順・テスト配置では一度も詰まらなかった**。詰まったのは次の 3 つ。

| 詰まり | 種類 |
|---|---|
| dev サーバのビルド監視が死んでいた | 環境(別 PR で解消済み) |
| パスパラメータが使えない / DELETE の前例がない | **規約の不記載** |
| Base UI の hidden input で E2E ロケータが二重マッチ | **ライブラリ挙動の不記載** |

つまり不足していたのは手順ではなく**制約と判断基準**だった。この結果は「CLAUDE.md は判断基準に絞る」という方針と整合する。

## 作業

### 1. `.claude/skills/` に 4 つのスキルを新設

`.claude/skills/<name>/SKILL.md`(frontmatter に `name` / `description`)。

| スキル | 内容 |
|---|---|
| `db-schema-change` | schema.prisma 編集 → `db:migrate:create` → `db:migrate:deploy` → `db:generate` → 生成物をコミット。`@db.Date` の制約と RLS 用 `tenantId` の付け方を含む |
| `add-api-endpoint` | ルートファイルの命名と配置 → モデル関数 → 統合テストの 1:1 配置 → `pnpm gen:openapi` → フロントの `$api` 呼び出し |
| `verify` | `pnpm verify` の内訳と、落ちたときの切り分け順。`pnpm knip` のベースライン差分の読み方 |
| `record-docs` | 計画 / 決定 / 保留の振り分けと、ADR・known-issues のテンプレート |

`.gitignore` は `**/.claude/settings.local.json` のみ除外しているので、`skills/` はコミットされる。

### 2. CLAUDE.md を再構成

- **冒頭に「まずどこを見るか」の索引**を置く(やりたいこと → 参照先 / スキル)
- 手順の本文は削除し、スキルへのポインタに置き換える
- README と重複する立ち上げ手順は README に一本化
- **受け入れテストで空白と分かった 2 点を判断基準として追記**する
  - ロールによる行レベルの可視範囲は **モデルの純粋関数(where ビルダー)に寄せる**(route で分岐しない)
  - 操作者の属性が必要なときは `models/users.ts` に取得関数を足す(`requireAdmin` の隣)
- 目標は 238 行 → 160 行前後。**内容を削るのではなく、手順をスキルへ移すことで減らす**

### 3. ADR を残す

`docs/decisions/20260804-agent-docs-structure.md`。「なぜ CLAUDE.md に手順が書いていないのか」は後から必ず疑問になり、**手順を本文へ書き戻す逆行**が起きやすいため。

## 検証

- `pnpm verify` 緑(ドキュメント変更のみなので影響はないはずだが、CLAUDE.md の記述と実態の整合を確認する過程で差分が出る可能性がある)
- CLAUDE.md に残した記述が**実態と合っているか**を、参照実装とコマンドで確認する(前回 README で `npx tsx script/seed.ts` の誤りを踏んでいる)
- スキルの手順を**実際に 1 度なぞって**、コマンドが通ることを確認する
