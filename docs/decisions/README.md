# Architecture Decision Records

この雛形の**主要な設計判断と、その根拠・却下した選択肢**を記録する場所。

目的は「なぜこのスタックなのか」を残すことで、**エージェントが良かれと思って逆行する提案(モックの追加、Date 自動変換の復活、service 層の新設、キャッシュの有効化など)を予防する**こと。各 ADR の末尾に「エージェント向けの注意」を置いている。

## ファイル名の規約

```
YYYYMMDD-<slug>.md      例: 20260713-datetime-design.md
```

- **日付は「決定日」**。ADR が書かれた日ではなく、その方針を採用した日を使う
- **改定してもリネームしない。** 日付を動かすと参照が壊れ、決定日という意味も失われるため。方針を変えたときは**本文の先頭付近に改定履歴を追記する**(実例: `20260803-ui-stack.md` のフォームライブラリの項)
- 同じ日に複数の決定があってもよい(slug が異なるため衝突しない)
- 連番は使わない。引用はファイル名かタイトルで行う
