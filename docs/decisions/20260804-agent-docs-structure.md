# ADR: CLAUDE.md は判断基準だけを持ち、手順は `.claude/skills/` に置く

- 状態: **採用**(2026-08-04)
- 関連: `docs/plans/20260804-claude-md-restructure.md`、`docs/template-repo-workplan.md` の 4-2

## 背景

CLAUDE.md は**毎セッション全文がコンテキストに載る**。一方で内容には頻度の異なる 3 種類が混在していた。

| 種類 | 例 | 必要になる頻度 |
|---|---|---|
| **判断基準** | 層構造は 3 層 / RHF は購読 API 縛り / 日時は JST 正準形 | 常時 |
| **地図** | 主要ファイルの場所 / ドメイン概念 | 常時 |
| **手順** | schema.prisma 編集 → `db:migrate:create` → `db:migrate:deploy` → `db:generate` | スキーマを変えるときだけ |

再構成前は 238 行で、その約 3 割が手順だった。

2026-08-04 の受け入れテスト(新規セッションのエージェントに「お知らせ CRUD を追加して」を丸投げ)で、**エージェントは層構造・スキーマ変更手順・テスト配置では一度も詰まらず**、詰まったのは次の 3 点だった。

| 詰まり | 種類 |
|---|---|
| dev サーバのビルド監視が死んでいた | 環境(ADR `20260804-dev-server.md` で解消) |
| パスパラメータが使えない / DELETE の前例がない | **制約の不記載** |
| Base UI の hidden input で E2E ロケータが二重マッチ | **ライブラリ挙動の不記載** |

**不足していたのは手順ではなく制約と判断基準だった。**

## 決定

**CLAUDE.md は「全体地図 + 判断基準」だけを持つ。手順は `.claude/skills/` のプロジェクトスキルに置く。**

新設したスキルは 4 つ。

| スキル | 対象 |
|---|---|
| `db-schema-change` | DB スキーマ変更・マイグレーション・Prisma クライアント再生成 |
| `add-api-endpoint` | ルートの命名と配置・モデル関数・統合テストの 1:1 配置・OpenAPI 型の受け渡し |
| `verify` | `pnpm verify` の内訳と切り分け・`pnpm knip` のベースライン差分の読み方 |
| `record-docs` | 計画 / 決定 / 保留の振り分けと、ADR・known-issues のテンプレート |

CLAUDE.md の冒頭には「**最初に見るところ**」の索引表を置き、やりたいことからスキルや ADR に飛べるようにした。

### 判断の分かれ目

**「これは常に効いている制約か、それとも特定の作業のときだけ辿る道順か」**で振り分ける。

- 常に効いている(破ると verify が落ちる、設計が壊れる)→ **CLAUDE.md**
- 特定の作業のときだけ必要な順序・コマンド → **スキル**

## 却下した選択肢

- **すべて CLAUDE.md に置いたまま、章立てだけ整理する**: 読みやすくはなるが、手順が常時コンテキストを占める問題は残る。判断基準の密度が下がると、**本当に守ってほしい制約が埋もれる**
- **手順も含めて `docs/` に置き、CLAUDE.md からリンクするだけにする**: スキルと違って**自動では引かれない**。「リンク先を読むべき状況」をエージェント自身が判断する必要があり、読まれないまま進む事故が起きやすい
- **スキルを 1 本にまとめる**(例: `dev-workflow`): 呼び出し条件が曖昧になり、スキーマ変更だけしたいときにも API 追加やドキュメント記録の手順が丸ごと載る

## エージェント向けの注意

- **手順を CLAUDE.md に書き戻さないこと。** 「CLAUDE.md にコマンドが載っていないから不親切」に見えるが、意図的に外している。追記したくなったら、それが**常に効いている制約**なのか**特定作業の道順**なのかを先に判定する
- **スキルと CLAUDE.md で内容が重複したら、スキル側を正とする**(手順はスキルが持つ)。ただし「lint で強制していること」「RHF の 3 制約」のような**制約**は CLAUDE.md が正
- 新しい定型手順(デプロイ、E2E の追加など)が生まれたら、**CLAUDE.md ではなく `.claude/skills/` に足す**
- `.claude/settings.local.json` は `.gitignore` 済み(個人の権限設定)。**`.claude/skills/` はコミットする**(リポジトリの資産)
- スキルの記述が実態とずれていたら、**コードではなくスキルを直す**。ずれたまま放置されたスキルは、間違った手順を毎回再生産する
