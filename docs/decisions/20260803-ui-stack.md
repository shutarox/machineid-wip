# ADR: UI スタックに Tailwind + shadcn/ui(Base UI)+ react-hook-form を採用する

- 状態: **採用**(2026-08-03)
- 関連: `docs/template-repo-workplan.md` の 3e、`docs/plans/20260803-ui-shadcn-plan.md`

## 改定履歴

| 日付 | 内容 |
|---|---|
| 2026-08-03 | 初版。スパイク 4 項目の判定を踏まえ、フォームは **TanStack Form** を採用 |
| 2026-08-03 | **フォームを react-hook-form に戻した。** 「RHF は React Compiler と併用できない」という判定が誤りで、推奨 API(`useFormState` / `useWatch` / `useController`)を使えばメモ化下でも動くと実測で判明したため。詳細は下記 (4) |

## 背景

雛形リポジトリの UI は旧プロダクト由来の **Chakra UI 2 + Ark UI + SCSS 分離**で、workplan の技術方針(Tailwind + shadcn/ui)に未移行だった。移行の狙いは基本原則 6「独自抽象は最小化し、エージェントが学習済みのエコシステム標準に寄せる」。

採用の可否は思想ではなく実測で決める方針とし、workplan 3e のスパイク 4 項目を検証した。

## 決定

| 項目 | 決定 | 根拠 |
|---|---|---|
| CSS | **Tailwind CSS v4**(`@tailwindcss/vite`) | Vite 8(Rolldown)で本番ビルドが通ることを確認。Vite 8 対応は 4.2.2 以降 |
| コンポーネント | **shadcn/ui**(CLI でソース同梱) | 生成物がプロジェクト内のソースとして残るため、エージェントが読める・直せる |
| プリミティブ | **Base UI** | shadcn/ui が 2026-07 に既定を Base UI へ変更(Radix も併走維持)。雛形は長寿命なので上流の既定に乗る |
| バリアント | **cva**(class-variance-authority) | shadcn 生成物が標準採用 |
| クラス名 lint | **eslint-plugin-better-tailwindcss** の correctness 群 | `eslint-plugin-tailwindcss` は v4 対応が beta 止まり |
| フォーム | **react-hook-form**(推奨 API 縛り) | Compiler との相性は実測で解決。事前知識量を優先(下記) |
| トースト | **sonner** | React ツリー外(QueryCache/MutationCache の onError)から呼べることが必須要件 |

## 検証結果

### (1) DatePicker / 時刻入力 / 大型テーブル

shadcn/ui にカレンダーの既製品はなく Base UI にもカレンダーのプリミティブはないため、Base UI の Popover の上に月グリッドを自前で実装した(`components/ui/DatePicker.tsx`)。日付の純粋関数は `libs/dateParts.ts` に分離し、`Date.toISOString()`(UTC 変換)を使わずローカル年月日で扱う。時刻入力(`components/ui/TimeInput.tsx`)は `930` / `9:5` のような省略入力を blur で `HH:mm` へ正規化する。

いずれも実用水準で組めたため**雛形に残す**。挙動は `e2e/uiComponents.spec.ts` が固定する。大型テーブルは 3e-2 の `UsersAdmin` 書き直しで判定する。

### (2) クラス名 lint + cva

`correctness` 群で **存在しないクラス(`flexx`)と競合するクラス(`p-4` と `p-8`、`text-red-500` と `text-blue-500`)が error として検出される**ことを実際に確認した。整形系のルール(line-wrapping 等)は prettier と衝突するため採用しない。

移行期は SCSS 由来の className が `no-unknown-classes` に引っかかるため、`eslint.config.js` に明示的な ignore リストを置いている。**このリストは残件リストを兼ねる**ので、Chakra / SCSS を全廃する 3e-3 で ignore ごと削除する。

### (3) Radix vs Base UI

shadcn/ui が 2026-07 に Base UI を既定化し、Radix も非推奨化せず併走させている。必要なプリミティブ(Dialog / Select / DropdownMenu / Drawer / Popover / Input / Button)はいずれも Base UI 1.6 に揃っている。**Base UI を採用**し、Radix との比較スパイクは行わなかった。

### (4) フォームライブラリ: react-hook-form(推奨 API 縛り)

3b で、react-hook-form の `formState`(レンダー中の読み取りを追跡する Proxy)が React Compiler の自動メモ化と相性が悪く、ボタン活性が追従しなくなることを `e2e/formState.spec.ts` で実証した。回避策として useForm を使う 4 コンポーネントに `'use no memo'` を付けていた。3e ではこれを根拠に **TanStack Form へ移行した**(`'use no memo'` なしで同 spec を無改変通過することを確認済み)。

**しかしこの根拠は誤りだった(2026-08-03 に訂正)。** 「RHF は Compiler と併用できない」のではなく、**壊れる書き方と壊れない書き方があり、3b の実装は壊れる方だった**というのが正確。3b 当時のコード(`22c7033`)は RHF が Compiler 下で避けるよう案内している書き方を 3 つとも踏んでいた。

| 3b 当時の書き方 | RHF 推奨 |
|---|---|
| `formState: { isDirty, isValid }` を `useForm()` から分割代入 | `useFormState({ control })` |
| `register()` + `reset(data)` の併用 | 値を再書き込みするなら `Controller` / `useController` |
| `PasswordReset` の `watch()` | `useWatch({ name, control })` |

#### 実測(2026-08-03)

推奨 API に直した RHF で、**Compiler のメモ化が効いた状態のまま `e2e/formState.spec.ts` を無改変で通過した**。

```
curl http://localhost:<port>/src/pages/Login.tsx             → _c(58)
curl http://localhost:<port>/src/pages/PasswordChange.tsx    → _c(37)
curl http://localhost:<port>/src/pages/PasswordReset.tsx     → _c(3)
curl http://localhost:<port>/src/pages/debug/DebugParamsModal.tsx → _c(5)
```

メモ化の確認は **dev サーバーが返す変換結果**で行う。本番バンドルを grep する方法は Rolldown がシンボルをリネームするため使えない(3e-1 で誤判定した)。

#### 決定: react-hook-form に戻す(2026-08-03、ユーザー判断)

| | react-hook-form | TanStack Form |
|---|---|---|
| 月次ダウンロード(2026-07) | **251M** | 10M |
| 1 年前(2025-08) | 65.5M | 1.4M |
| 比率の推移 | 46:1 → 25:1(差は縮小中) |

RHF が推奨 API で問題なく動く以上、**エージェントの事前知識量が 25 倍あること**が決め手になる。この雛形は「エージェントが参照実装を模倣して自走できること」を受け入れテストにしているため、学習データの厚みは実利がある。

**採用にあたっての制約(必ず守ること)**

- `formState` は `useForm()` の戻り値から分割代入せず、**`useFormState({ control })`** で購読する
- 値を購読するときは `watch()` ではなく **`useWatch({ name, control })`**
- **`reset()` で値を書き換えるフィールドは `register` ではなく `useController` / `Controller`** でバインドする(`register` は Compiler 下で内部 `_reset` を越えられない)
- **`'use no memo'` は使わない**。使わずに済む書き方が上記であり、リポジトリ内に 1 つも無い状態を維持する

この 3 つは **lint では検出できない**ため、`e2e/formState.spec.ts` が唯一の検出装置になる。フォームを追加・変更したらこの spec を必ず流すこと。

#### TanStack Form を却下した理由

思想的には TanStack Form の方が安全(selector 購読しか API がなく、壊れる書き方が存在しない)。ただし本リポジトリでは 3e で一度移行して**実際に動くことを確認済み**であり、いつでも戻せる。その前提で、事前知識 25:1 の差を優先した。

**再検討する条件**: RHF の推奨 API 縛りが実務で守られないと分かったとき(= `formState.spec.ts` が壊れる変更が繰り返されるとき)、または RHF v8 で API が大きく変わったとき。

## 実装上の注意(移行で踏んだもの)

- **shadcn CLI はルートの `tsconfig.json` の `compilerOptions.paths` しか見ない**。本リポジトリは project references 構成(ルートは `files: []` + `references`)なので、ここに `paths` を書かないと `frontend/@/lib/utils.ts` のような literal ディレクトリが生成される。**`baseUrl` は不要**で、1-16 で廃止した状態(3f の前提)を維持できる
- **移行期は Tailwind の preflight を入れない**。Chakra 2 の CSS reset と `src/reset.css` が生きているため競合する。`@import 'tailwindcss'` を分解し theme / utilities のみ読み込んでいる。3e-3 で通常形へ戻す
- **移行期は utilities を CSS レイヤーに入れない**。Chakra は emotion でスタイルを**レイヤー外**に注入する。CSS のカスケードではレイヤー外の宣言がレイヤー内の宣言に詳細度と無関係に勝つため、`layer(utilities)` に入れると Chakra の `*` リセット(`border-width: 0` 等)に負けて **Tailwind の枠線・余白ユーティリティが一切効かない**。実際に枠線が消える形で踏んだ。Chakra 全廃後は通常形(レイヤーあり)に戻す
- **サーバ値をフォームに入れるときは、取得完了までフォームをマウントしない**。「先にマウントして effect で `reset(data)` 同期」にすると、(a) 取得完了が入力より後になったときに入力が消える (b) remount 直後の `reset()` がフォーム初期化に上書きされて空欄になる、の 2 つの競合を踏む。取得値をそのまま `defaultValues` に渡す形にすれば起きない。回帰テストは `e2e/formState.spec.ts` の「保存済みの疑似日時が開き直しても復元される」
- shadcn の sonner テンプレートは `next-themes` に依存する。ダークモード切替を持たない Vite アプリなので依存ごと外してテーマを固定した

## 影響

- 移行は 3 PR に分割する(基盤導入 + スパイク → 参照実装の書き直し → Chakra / Ark / SCSS 全廃)
- useForm を使う 4 コンポーネント(`Login` / `PasswordChange` / `PasswordReset` / `DebugParamsModal`)はすべて推奨 API 縛りの RHF で書かれ、`'use no memo'` は付いていない
- 不合格だった場合の代替(Mantine との再比較)は不要になった

## 却下した選択肢

- **Radix**: 成熟しているが、shadcn の新規既定から外れたぶん今後のサンプルと情報が Base UI 寄りになる
- **`'use no memo'` での回避**: Compiler の恩恵をフォーム画面で捨てることになる。推奨 API を使えば不要なので採らない
- **eslint-plugin-tailwindcss**: v4 対応が beta 止まり
